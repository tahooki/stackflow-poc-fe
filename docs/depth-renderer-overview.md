# 뎁스 렌더러 개요

## 왜 만드는지
- 스택이 깊어질수록 DOM에 남아있는 화면이 많아져 렌더 비용과 메모리 사용이 커진다.
- 스택 히스토리는 유지하되, 화면 렌더링만 제한해서 성능을 안정화하려는 목적이다.
- “오래된 화면을 완전히 삭제”하는 코어 API가 없으므로 렌더러 레벨에서 해결한다.

## 무엇을 하는지
- Stackflow 렌더러에서 `stack.render().activities` 결과를 필터링한다.
- 깊이가 `maxVisible`을 넘으면 오래된 화면을 DOM에서 제외한다.
- 제외된 화면은 언마운트되어 렌더/메모리 비용을 줄인다.
- 스택 히스토리는 그대로 유지되며, back 동작 시 다시 렌더될 수 있다.

## 대략적인 로직
1. 현재 스택의 렌더 가능한 activity 목록을 가져온다.
2. `exit-done` 상태는 기본 렌더러처럼 제외한다.
3. `maxVisible` 기준으로 최근 N개만 남기고 나머지는 렌더 트리에서 제거한다.
4. 제거된 화면은 언마운트되고, 다시 범위에 들어오면 리마운트된다.

## 주의사항
- 재등장 시 리마운트가 발생하므로 상태/스크롤 복원 비용이 생길 수 있다.
- `maxVisible`은 config로 주입하며, stack별 override를 지원하는 것을 전제로 한다.
